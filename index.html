🛡️ Deployment, Cloud Database & Security Blueprint

How to Publish Your Link, Connect a Database & Prevent Data Leaks

Follow this production architecture to share a secure web link with your field technicians/POCs, persist every daily update in a real-time cloud database, and lock down sensitive PO and site data with enterprise authentication and Row-Level Security (RLS).

1

Publish & Share Private Link

Cloudflare Pages, Vercel, or Netlify

  1. Download this HTML file (index.html) inside a private GitHub repository or folder.
  2. Deploy on Cloudflare Pages or Vercel (Free, global HTTPS/TLS encryption out of the box): connect your private GitHub repo and deploy in 30 seconds to get a link like https://tracker.yourcompany.ae.
  3. Enable Zero-Trust Access Gate: In Cloudflare Zero Trust (free up to 50 users), add an Access Application Policy so only technicians with approved company emails or a one-time PIN can even load the link.
2

Connect Real-Time Cloud DB

Supabase (PostgreSQL) Multi-Day Sync

  1. Create a Supabase Project (supabase.com) — gives you a managed PostgreSQL database, Authentication, and instant REST/Realtime APIs.
  2. Run the SQL Schema below in the Supabase SQL Editor to create tracker_reports, material_usage_entries, and catalog_items.
  3. Multi-Day Persistence: When a technician logs materials today and adds extra quantities tomorrow, upsert updates the central PostgreSQL row and records an immutable entry in audit_history.
3

Lock Down & Prevent Leaks

5-Layer Enterprise Security Controls

  • Row-Level Security (RLS): Technicians can only view/edit reports assigned to their authenticated user ID; only Admin/PM accounts can view all sites.
  • Strip Unit Prices from Field View: Keep commercial AED unit prices in a restricted boq_pricing table inaccessible to technician roles.
  • Magic Link / OTP Login: Require email/SMS OTP login before loading the catalog JSON from the server (never ship sensitive data to unauthenticated visitors).
  • Audit Trail & Soft Deletes: Block DELETE for field roles so rows cannot be wiped maliciously.

Production PostgreSQL / Supabase Schema + Row-Level Security (RLS)

Copy and paste into Supabase SQL Editor to set up your tables and leak-proof access policies.

-- 1. Tracker Reports Table (Header Metadata)
create table public.tracker_reports (
  id uuid primary key default gen_random_uuid(),
  title text not null,
  created_date date not null default current_date,
  poc_name text not null,
  poc_user_id uuid references auth.users(id) not null,
  status text not null default 'Ongoing (Multi-Day Editable)',
  updated_at timestamptz not null default now()
);

-- 2. Material Usage Entries Table (Daily Site Material Logs)
create table public.material_usage_entries (
  id uuid primary key default gen_random_uuid(),
  report_id uuid references public.tracker_reports(id) on delete cascade not null,
  usage_date date not null,
  site_code text not null,
  material_name text not null,
  quantity numeric(12,2) not null check (quantity > 0),
  uom text not null,
  poc_name text not null,
  remarks text default '',
  updated_by uuid references auth.users(id),
  updated_at timestamptz not null default now()
);

-- 3. Enable Row-Level Security (RLS) to Prevent Data Leaks
alter table public.tracker_reports enable row level security;
alter table public.material_usage_entries enable row level security;

-- Policy A: Field Technicians can only read/write their own reports (Admins see all)
create policy "Technicians access own reports or Admin sees all"
on public.tracker_reports for all
to authenticated
using (auth.uid() = poc_user_id or (auth.jwt() -> 'app_metadata' ->> 'role') = 'admin')
with check (auth.uid() = poc_user_id or (auth.jwt() -> 'app_metadata' ->> 'role') = 'admin');

-- Policy B: Entries inherit access from their parent report
create policy "Technicians manage entries in authorized reports"
on public.material_usage_entries for all
to authenticated
using (
  exists (
    select 1 from public.tracker_reports r
    where r.id = material_usage_entries.report_id
      and (r.poc_user_id = auth.uid() or (auth.jwt() -> 'app_metadata' ->> 'role') = 'admin')
  )
);
